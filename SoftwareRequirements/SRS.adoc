== Introdução

No cenário econômico atual, a gestão eficiente das finanças pessoais tornou-se uma competência essencial para a estabilidade e o alcance de objetivos a longo prazo. Entretanto, a fragmentação de gastos e a falta de registros claros muitas vezes impedem que indivíduos tenham uma visão real de sua saúde financeira.

O projeto Fin-Flow surge como uma solução tecnológica projetada para simplificar esse controle. Trata-se de um aplicativo móvel voltado para a plataforma Android , que combina praticidade e segurança para permitir que usuários finais gerenciem receitas, despesas e metas de economia em um único local. Por meio de uma interface intuitiva e relatórios visuais , o sistema visa transformar dados brutos em informações estratégicas, auxiliando na tomada de decisões financeiras conscientes e em conformidade com as diretrizes da Lei Geral de Proteção de Dados (LGPD).

=== Finalidades

* Centralizar o controle financeiro em um único aplicativo.
* Facilitar o registro de receitas e despesas, com categorias personalizadas.
* Acompanhar saldos e metas financeiras, mostrando o progresso de forma clara.
* Gerar relatórios e gráficos que ajudam a entender melhor os hábitos de
consumo.
* Garantir segurança dos dados, respeitando a privacidade do usuário.
* Apoiar a tomada de decisões, oferecendo informações confiáveis e acessíveis

== Definições, Acrônimos e Abreviações

=== Definições

* *Fin-Flow* – Aplicativo móvel de gerenciamento financeiro pessoal voltado ao controle de receitas, despesas, metas e relatórios financeiros.

* *Usuário* – Pessoa física que realiza cadastro no sistema para gerenciar suas finanças pessoais.

* *Receita* – Valor monetário recebido pelo usuário (ex: salário, bônus, vendas).

* *Despesa* – Valor monetário gasto pelo usuário (ex: contas, compras, serviços).

* *Saldo* – Resultado da diferença entre o total de receitas e o total de despesas.

* *Categoria* – Classificação utilizada para organizar receitas e despesas (ex: Alimentação, Transporte, Lazer).

* *Meta Financeira* – Objetivo monetário definido pelo usuário para economia ou investimento.

* *Relatório Financeiro* – Representação visual ou textual dos dados financeiros do usuário, podendo incluir gráficos e tabelas.

* *Autenticação* – Processo de verificação da identidade do usuário para acesso ao sistema.

* *Administrador do Sistema* – Responsável pela manutenção geral e gerenciamento da aplicação.

=== Acrônimos

* *RF – Requisito Funcional*  
Descrição de uma funcionalidade que o sistema deve executar.  
Define comportamentos, ações ou serviços que o sistema deve oferecer ao usuário.

* *RNF – Requisito Não Funcional*  
Define características de qualidade do sistema, como desempenho, segurança, usabilidade e disponibilidade.  
Não descreve o que o sistema faz, mas como ele deve se comportar.

* *R – Restrição*  
Limitação técnica, legal, financeira ou operacional que impacta o desenvolvimento do sistema.

* *BD – Banco de Dados*  
Sistema responsável pelo armazenamento, organização e recuperação das informações do aplicativo.

* *API – Application Programming Interface*  
Conjunto de regras e padrões que permitem a comunicação entre sistemas ou componentes de software.

* *UI – User Interface*  
Interface do Usuário.  
Parte visual do sistema com a qual o usuário interage (telas, botões, menus).

* *UX – User Experience*  
Experiência do Usuário.  
Refere-se à percepção e satisfação do usuário ao utilizar o sistema.

* *CRUD – Create, Read, Update, Delete*  
Conjunto das quatro operações básicas realizadas em um banco de dados:  
Criar, Ler, Atualizar e Excluir dados.

* *LGPD – Lei Geral de Proteção de Dados*  
Legislação brasileira que regula o tratamento de dados pessoais, garantindo privacidade e segurança das informações.

== Visão Geral do Sistema Fin-Flow

O Aplicativo *Fin-Flow* tem como objetivo auxiliar usuários no controle de suas finanças pessoais, permitindo registrar receitas e despesas, acompanhar saldos, definir metas financeiras e visualizar relatórios que apoiem a tomada de decisões financeiras.

O sistema será voltado para dispositivos móveis (Android), com possibilidade de expansão para versão web.

== Stakeholders (Partes Interessadas)

=== Usuário Final
* Pessoa física que deseja controlar seus gastos e receitas.

=== Desenvolvedor
* Responsável pela implementação e manutenção do sistema.

=== Administrador do Sistema
* Responsável por gerenciar usuários, categorias padrão e manutenção geral.

== Requisitos Funcionais (RF)

Os requisitos funcionais descrevem o que o sistema deve fazer.

=== RF01 – Cadastro de Usuário

O sistema deve permitir que o usuário realize cadastro utilizando:

* E-mail e senha;
* Ou autenticação via Google.

=== RF02 – Login e Autenticação

O sistema deve permitir que o usuário faça login de forma segura e mantenha a sessão ativa.

* E-mail e senha.

=== RF03 – Registro de Receitas

O sistema deve permitir que o usuário:

* Cadastre receitas (recebimento);
* Informe valor;
* Data;
* Categoria;
* Descrição.

=== RF04 – Registro de Despesas

O sistema deve permitir que o usuário:

* Cadastre despesas;
* Informe valor;
* Data;
* Categoria;
* Forma de pagamento;
* Descrição.

=== RF05 – Gerenciamento de Categorias

O sistema deve permitir:

* Criar, editar e excluir categorias de receitas e despesas;
* Utilizar categorias padrão (ex: alimentação, transporte, lazer).

=== RF06 – Visualização de Saldo

O sistema deve calcular automaticamente:

* Saldo atual;
* Total de receitas;
* Total de despesas.

=== RF07 – Relatórios Financeiros

O sistema deve gerar relatórios:

* Mensais;
* Semanais;
* Em formato de gráficos (pizza, barras).

=== RF08 – Definição de Metas Financeiras

O sistema deve permitir que o usuário:

* Defina metas de economia;
* Acompanhe o progresso das metas.

=== RF09 – Exportação de Dados

O sistema deve permitir exportar dados financeiros em formato:

* PDF;
* CSV.

== Requisitos Não Funcionais (RNF)

Os requisitos não funcionais descrevem como o sistema deve se comportar.

=== RNF01 – Usabilidade

O sistema deve possuir interface simples, intuitiva e responsiva.

=== RNF02 – Segurança

* As senhas devem ser criptografadas;
* O sistema deve seguir boas práticas de segurança (ex: HTTPS).

=== RNF03 – Desempenho

* O sistema deve responder às ações do usuário em até 2 segundos.

=== RNF04 – Disponibilidade

* O sistema deve estar disponível 24 horas por dia, exceto em períodos de manutenção.

=== RNF05 – Compatibilidade

* O sistema deve funcionar em dispositivos Android versão 8.0 ou superior.

== Restrições do Sistema – FinFlow

As restrições do sistema FinFlow definem os limites técnicos, legais e operacionais que devem ser respeitados durante o desenvolvimento, garantindo viabilidade, segurança e conformidade do projeto.

=== R01 – Restrição Tecnológica

O sistema deverá ser desenvolvido exclusivamente para a plataforma mobile Android, utilizando linguagem e framework definidos pela equipe (ex: Kotlin ou Flutter).

*Justificativa:*

* Público-alvo inicial utiliza majoritariamente Android;
* Redução de complexidade no desenvolvimento;
* Limitação de recursos da equipe.

*Impacto:*

* O sistema não estará disponível para iOS na primeira versão;
* Funcionalidades deverão respeitar limitações da API Android.

=== R02 – Restrição de Banco de Dados

O sistema deverá utilizar banco de dados relacional para armazenamento das informações financeiras dos usuários.

*Justificativa:*

* Estrutura organizada para dados financeiros;
* Facilidade de modelagem com chaves primárias e estrangeiras;
* Compatibilidade com arquitetura acadêmica.

*Impacto:*

* Necessidade de modelagem correta (MER);
* Garantia de integridade referencial.

=== R03 – Restrição de Conectividade

Algumas funcionalidades poderão depender de conexão com a internet, como:

* Backup em nuvem;
* Exportação online;
* Atualizações do sistema.

*Justificativa:*

* Segurança dos dados;
* Possibilidade de sincronização futura.

*Impacto:*

* Sistema deve prever modo offline para funções básicas;
* Deve tratar falhas de conexão adequadamente.

=== R04 – Restrição Legal (LGPD)

O sistema deverá estar em conformidade com a Lei Geral de Proteção de Dados (LGPD), garantindo:

* Consentimento do usuário para armazenamento de dados;
* Possibilidade de exclusão de conta;
* Proteção contra vazamento de informações.

*Justificativa:*

* Dados financeiros são altamente sensíveis;
* Exigência legal no Brasil.

*Impacto:*

* Implementação de criptografia;
* Política de privacidade obrigatória.

=== R05 – Restrição de Prazo

O desenvolvimento do sistema deverá ser concluído dentro do prazo acadêmico estabelecido.

*Justificativa:*

* Entrega vinculada à avaliação da disciplina.

*Impacto:*

* Algumas funcionalidades poderão ser simplificadas;
* Priorização dos requisitos essenciais.

=== R06 – Restrição Orçamentária

O projeto deverá ser desenvolvido utilizando ferramentas gratuitas ou de código aberto.

*Justificativa:*

* Projeto acadêmico sem financiamento externo.

*Impacto:*

* Uso de serviços gratuitos;
* Limitação de servidores pagos.

=== R07 – Restrição de Complexidade

O sistema deverá manter arquitetura simples e de fácil manutenção, considerando o nível técnico da equipe desenvolvedora.

*Justificativa:*

* Projeto acadêmico;
* Garantir que todos os membros consigam implementar e entender o código.

*Impacto:*

* Evitar tecnologias muito avançadas;
* Estrutura modular simples.

=== R08 – Restrição de Dispositivo

O sistema deverá funcionar adequadamente em dispositivos Android versão 8.0 ou superior.

*Justificativa:*

* Compatibilidade com maioria dos dispositivos ativos;
* Evitar uso de APIs muito recentes.

*Impacto:*

* Interface deve ser leve;
* Controle de consumo de memória.
